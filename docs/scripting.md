# Сценарии в командной строке

Командная строка стратегии — это аргументы движка с `# комментариями` и ссылками `{…}`.
Строки, начинающиеся с `@`, — директивы: их выполняет приложение, а движок получает обычные
аргументы. Текст без директив передаётся движку как есть.

Где писать: *Настройки → Стратегия → своя* (поле аргументов). Под полем видно, что получит
движок в Wi-Fi и в мобильной сети, ошибки с номером строки и переключатели блоков `@block`.

Сеть различается только по типу: `wifi` или `mobile`. Имя Wi-Fi не используется: на
Android 10+ для него нужно разрешение на местоположение. Если в стратегии есть `@if`, при
смене типа сети движок перезапускается с текстом, собранным для новой сети. Туннель при этом
остаётся, открытые соединения рвутся, приложения переподключаются сами.

<a id="переменные-блоки-условия"></a>
<details>
<summary><b>Переменные, блоки, условия</b></summary>

```
@set sni = www.google.com              # переменная, дальше $sni или ${sni}
@include "Discord termux"              # стратегия из «Моих стратегий» по названию
@block YouTube                         # именованный блок: его можно выключить в интерфейсе
  --hosts {list:youtube} -C {proxy:termux} --auto=none
@end
@if mobile                             # wifi | mobile | not wifi | !mobile
  --tlsrec 1+s
@else
  --disorder 1
@end
--fake -1 --fake-sni $sni
```

`@include` разрешает вложенность до 5 уровней. Если стратегия включает сама себя, это
ошибка. Неизвестная переменная — тоже ошибка.

</details>

<a id="подбор-прямо-в-стратегии-try-и-fallback"></a>
<details>
<summary><b>Подбор прямо в стратегии: <code>@try</code> и <code>@fallback</code></b></summary>

```
@sites discord = discord.com gateway.discord.gg cdn.discordapp.com
@for discord
@try
  --disorder 1
@or
  --oob 3
@or
  -C {proxy:termux}
@end
```

<details>
<summary><b><code>@try</code></b></summary>

Каждый вариант становится отдельной группой движка (слотом). Сайты из `@for`
лежат в слоте победителя, пока движок работает.

</details>

Что происходит при старте VPN:

- если победитель для этой сети уже известен, сайты сразу попадают в его слот, иначе — в
  слот первого варианта;
- если победителя нет или ему больше суток, приложение в фоне проверяет варианты тестовым
  движком вне VPN;
- выигрывает первый вариант, загрузивший все сайты, а если такого нет — лучший из
  проверенных;
- найденный вариант применяется без перезапуска движка и запоминается отдельно для `wifi` и
  `mobile`.

<details>
<summary><b><code>@fallback … @or … @end</code></b></summary>

Варианты без проверки заранее: они становятся группами движка
`--auto=torst,redirect,ssl_err`. При обнаруженной блокировке движок сам переходит к
следующему варианту. В варианте `@fallback` не может быть своих групп (`--auto`).

</details>

Внутри `@try` и `@fallback` допустимы только `@or` и `@end`.

</details>

<a id="реакции-на-события-журнала-on"></a>
<details>
<summary><b>Реакции на события журнала: <code>@on</code></b></summary>

```
@on <причины> [<домены>] [tcp|udp] [xN/T] -> <действие>
```

<details>
<summary><b>Причины</b></summary>

Их берут из журнала соединений движка, несколько можно перечислить через
запятую:

</details>

- `block` — сброс, редирект или ошибка TLS;
- `freeze` — зависание на 16–20 КБ;
- `noreply` — нет ответа на TLS;
- `connfail` — нет TCP-соединения;
- `udp-noreply` — UDP без ответа;
- `proxy-down` — прокси отказывает;
- `any` — всё, кроме `proxy-down`.

<details>
<summary><b>Домены</b></summary>

`example.com` или `*.example.com`, через запятую. В обоих случаях
поддомены тоже подходят. Без доменов правило действует для любого домена.

</details>

<details>
<summary><b>Порог</b></summary>

`x3/5m` означает «3 события за 5 минут». Единицы — `s`, `m`, `h`; окно не больше
24 часов.

</details>

<details>
<summary><b>Действия</b></summary>

`use <аргументы>` — домен переносится в слот с этими аргументами;
- `proxy <имя>` — то же, что `use -C {proxy:<имя>}`;
- `try { <аргументы> | <аргументы> … }` — варианты сначала проверяются в фоне, домен
  переносится в слот победителя;
- `autofix` — то же, что `try`, но с кандидатами автоподбора: пресеты, затем прокси из
  настроек;
- `notify` — уведомление;
- `ignore` — ничего не делать (и не проверять следующие правила).

</details>

```
@on freeze *.discord.com,discord.gg tcp -> proxy termux
@on noreply *.youtube.com,*.googlevideo.com x2/1m -> try { --disorder 1 | --oob 3 | -C {proxy:termux} }
@on udp-noreply udp -> use --udp-fake 6 --ttl 4
@on proxy-down -> notify
@on any *.doubleclick.net,mc.yandex.ru -> ignore
@on any x3/10m -> autofix
```

Пока VPN работает, приложение читает журнал текущей сессии. Срабатывает первое подходящее
правило. Действия переносят домен в слот без перезапуска движка: новые соединения идут
новой стратегией, открытые доживают со старой.

Защита от зацикливания:

- после срабатывания правило 10 минут не действует на тот же домен;
- всего не больше 30 действий в час.

Срабатывания пишутся в журнал строками `script: @on …`. Правила `@on` ставьте перед
основной стратегией.

</details>

<a id="что-пока-не-работает"></a>
<details>
<summary><b>Что пока не работает</b></summary>

`@restart`, `@restart-delay`, `@restart-idle`, `@restart-limit`, `@restart-keep`
  принимаются, но ничего не меняют. Варианты применяются через слоты, без перезапуска; движок
  перезапускается только при смене типа сети (если есть `@if`).
- `@scenario` (автомат «применить → проверить → повторить → эскалация») — ошибка
  «not supported yet». План: состояние на домен, условия проверки (`loaded`, `responded`,
  `quiet 2m`, `udp-reply`…), повторы и цепочка эскалаций.
- Добавить слот на лету нельзя. Все стратегии, которые могут понадобиться (варианты `@try`,
  действия `@on`, кандидаты `autofix`), становятся слотами при старте движка.

</details>

<a id="как-это-устроено-в-движке"></a>
<details>
<summary><b>Как это устроено в движке</b></summary>

Каждый вариант превращается в группу движка `--slot <имя>` с пустым списком доменов. Пока
движок работает, приложение переносит домен между слотами через JNI (`ByeDpi.assignSlot` →
`slot_assign` в движке). Списки слотов защищены мьютексом. Группа для соединения выбирается
при подключении по имени хоста, поэтому смена стратегии действует на новые соединения и
UDP-потоки сразу. Подробности — в [UPSTREAM.md](../app/src/main/cpp/engine/UPSTREAM.md)
(`--slot`).

</details>
