# Подбор стратегии и глубокая проверка

Два инструмента: «Подобрать стратегию автоматически» и «Глубокая проверка». Оба работают по
образцу `blockcheck` из zapret: перебирают стратегии и смотрят, какая открывает сайт. Их
можно запускать с включённым VPN или без него.

<a id="подбор-стратегии"></a>
<details>
<summary><b>Подбор стратегии</b></summary>

Каждая стратегия поднимается как локальный прокси, и выбранные сайты открываются через
него по HTTPS. Проверяются: установка соединения, TLS-рукопожатие с проверкой сертификата,
HTTP-ответ и до 128 КБ тела.

<details>
<summary><b>Сайты</b></summary>

«Быстрый» и «полный» наборы из встроенных групп (видео YouTube, Telegram, Discord,
соцсети, Cloudflare и др.) или свои — через пробел или запятую.

</details>

<details>
<summary><b>Без обхода</b></summary>

Перед перебором проверяются сайты без стратегии. Если все запросы проходят,
значит, эти сайты на вашей сети не заблокированы, и подбирать ничего не нужно.

</details>

<details>
<summary><b>Статусы строк</b></summary>

`✓` — сайт открылся, сервер ответил;
- `◐` — сервер ответил, но страница не загрузилась (обрыв или зависание);
- `✗` — не открылся.

</details>

Любой HTTP-ответ, даже 404 или 403, означает, что соединение прошло через DPI: статус — это
ответ самого сервера. Блокировка видна как сброс, таймаут, зависший или обрезанный ответ,
неверный сертификат или редирект на страницу блокировки.

<details>
<summary><b>Коды причин сбоя</b></summary>

`+` — открылся, `r` — сброс соединения, `t` — таймаут, `f` — зависание или короткое
тело ответа, `c` — нет TCP-соединения, `m` — ошибка сертификата.

</details>

<details>
<summary><b>TLS</b></summary>

Режим «авто», TLS 1.2, TLS 1.3, «обе» (каждая версия отдельно), «как Chrome»
(ClientHello Chrome с Kyber из zapret2) или «Android + Chrome».

</details>

<details>
<summary><b>Применить</b></summary>

Кнопка «Применить» ставит стратегию в настройки; потом переподключитесь.

</details>

<details>
<summary><b>Режим UDP</b></summary>

Проверяет QUIC (HTTP/3, UDP 443) каждого сайта: отправляется настоящий
QUIC Initial с именем сайта, любой ответ сервера засчитывается. Также проверяются STUN-серверы
звонков. Без root «UDP-desync» означает фейковые датаграммы с низким TTL перед настоящими.

</details>

<details>
<summary><b>Сообщество</b></summary>

Пункт «Сообщество ByeByeDPI» добавляет стратегии сообщества (около 60, число
в скобках). Параметр «SNI для фейковых пакетов» подставляется вместо `{sni}`. Списки стратегий
для подбора обновляются из репозитория вместе со встроенными списками.

</details>

<details>
<summary><b>Отчёт</b></summary>

Каждый прогон сохраняется отдельным файлом с кнопкой «Поделиться».

</details>

</details>

<a id="глубокая-проверка"></a>
<details>
<summary><b>Глубокая проверка</b></summary>

Проверяет все стратегии против сотен и тысяч доменов: из групп сайтов и хост-листов.

<details>
<summary><b>Запуск</b></summary>

Кнопка «Начать глубокую проверку». Домены берутся из групп сайтов и из
хост-листов; чтобы их добавить, скачайте списки в *Настройки → Списки хостов → Списки из
репозиториев*.

</details>

<details>
<summary><b>Что считается открытым</b></summary>

Домен засчитывается, только если удались все попытки.

</details>

<details>
<summary><b>Настройки прогона</b></summary>

Таймаут, число попыток, параллельность, паузы. Работает в фоне с
уведомлением, поэтому можно свернуть приложение. Прогон может идти часами.

</details>

<details>
<summary><b>Результат</b></summary>

Матрица `matrix.csv` (домен × стратегия), сводка и zip-архив для отправки.

</details>

<details>
<summary><b>Открытость</b></summary>

Ответ больше 64 КБ считается открытым. Обрыв на 16–20 КБ, характерный для
ТСПУ, отмечается отдельно. Цели с префиксом `big:` — не меньше 200 КБ, с переходом по
редиректам.

</details>

<details>
<summary><b>Группа «Discord полностью»</b></summary>

Проверяет шлюз приложения, сайт и CDN вместе.

</details>

</details>

<a id="мультистратегия-из-результатов"></a>
<details>
<summary><b>Мультистратегия из результатов</b></summary>

После глубокой проверки кнопка «Собрать мультистратегию» строит команду: главная стратегия
плюс до пяти дополнительных, каждая для своих доменов. Домены сохраняются как хост-листы
`multi_<время>_N`, поэтому сохранённая команда не ломается при следующих прогонах. Кнопка
«Перепроверить» прогоняет собранную команду по этим доменам.

Ручная сборка описана в [стратегиях](strategies.md#мультистратегия-вручную).

</details>

<a id="как-читать-результат"></a>
<details>
<summary><b>Как читать результат</b></summary>

Если «без обхода» все сайты открываются, менять стратегию не нужно.
- Если не открывает ни одна стратегия, включая «без обхода», проблема не в DPI: сервис
  может закрывать доступ по стране или IP-адресу. Для таких сервисов см. раздел «Сайты через
  прокси» в [быстром старте](quick-start.md#4-настроить-охват-по-желанию).
- Если открывается только в UDP-режиме, но не в TCP, или наоборот, нужна стратегия под
  нужный протокол; для звонков выбирайте «Discord и звонки».
- Сравнивайте не один сайт, а группу: стратегия, открывающая весь сервис, надёжнее той, что
  открыла только главную страницу.

</details>
