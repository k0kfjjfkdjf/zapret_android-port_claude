# История изменений

Раздел каждой версии автоматически попадает в описание её релиза на GitHub.

## Не выпущено

- Документация сверена с кодом: `docs/scripting.md` — справочник вместо плана, пресеты, пути в
  настройках, два канала сборок, автоматизация, приватность; разделы документации свёрнуты по
  умолчанию. Справка движка (`--help`) дополнена опциями форка.

## 0.0.1

**Первая стабильная сборка.** Ставится как приложение `io.github.zapretdroid` рядом с тестовой
(`.debug`); у стабильных сборок своя нумерация, обновление из приложения предлагает им только
стабильные релизы. Внутри — всё из тестовых сборок до 0.23.0 и исправления после проверки кода:

- **Безопасность:** автоматизация (ярлыки, Tasker, adb) больше не принимает от других приложений
  прокси, перенаправление DNS и файловые опции — раньше любое установленное приложение могло
  увести через неё трафик или DNS к себе. Обновление приложения ходит только по HTTPS.
- **Движок:** испорченный ClientHello при `--fake-tls-mod orig` / `--fake-sni` больше не вешает
  движок и не выходит за буфер; SOCKS5-запрос с неизвестным типом адреса отклоняется. Найдено
  фаззером.
- **UDP:** неотправляемая датаграмма больше не рвёт всю ассоциацию (звонки), `--udp-proxy`
  работает на сетях с IPv4 и IPv6, TTL сокета восстанавливается после неудачного фейка.
- **DoH:** управление потоком HTTP/2, отказ от слишком больших ответов.
- **Интерфейс ByeByeDPI:** переключение больше не сплющивает стратегию в одну строку и не ломает
  `{list:telegram}`; одинаковые сохранённые стратегии больше не роняют приложение; удалённое
  приложение в `{app:…}` больше не мешает запуску VPN.
- **Скрипты:** огромное число в пороге `@on … xN/T` — ошибка в строке, а не падение редактора.
- **Размер:** код ужат R8, неиспользуемые библиотеки (`ui-tooling`) убраны — APK в несколько раз
  меньше.

## 0.23.0

- **Пресеты стратегий обновляются без новой версии приложения** — как списки proxy/telegram.
  Они лежат в репозитории в `app/src/main/assets/strategies/presets.txt`:
  ```
  [auto]
  --disorder 1
  --auto=torst --tlsrec 1+s
  # если не помогло: фейки с разрешённым SNI
  --auto=torst,ssl_err --fake -1 --ttl 4 --fake-tls-mod rand,orig --fake-sni www.google.com

  [my_preset] Название | Описание
  --oob 3
  ```
  Правка в репозитории меняет командную строку пресета (или добавляет новый пресет), приложение
  забирает файл при проверке обновлений или по кнопке «Настройки → Встроенные списки и пресеты →
  Обновить сейчас». Файл проверяется перед заменой; если он испорчен, остаются встроенные пресеты.
- Так же обновляются списки стратегий для подбора (`strategies/*.list`).

## 0.22.1

- **Пресет «Адаптивная» получил третью ступень — фейки:** `--fake -1 --ttl 4 --fake-tls-mod rand,orig
  --fake-sni www.google.com`. Отчёты с двух телефонов в одной Wi-Fi показали противоположное: на
  одном проходит только разбиение (фейки ломают TLS), на другом — только фейки с TTL 4–6 (разбиение
  не проходит вовсе). Теперь пресет по умолчанию переходит к фейкам, если disorder и разбиение
  TLS-записей не помогли.

## 0.22.0

- **Скрипты, этап 3: реакции на события журнала** — `@on <причины> [домены] [tcp|udp] [xN/T] -> <действие>`:
  ```
  @on freeze *.discord.com,discord.gg tcp -> proxy termux
  @on noreply *.youtube.com,*.googlevideo.com x2/1m -> try { --disorder 1 | --oob 3 | -C {proxy:termux} }
  @on proxy-down -> notify
  @on any x3/10m -> autofix
  @on any *.doubleclick.net,mc.yandex.ru -> ignore
  ```
  Причины: `block`, `freeze` (зависание на 16–20 КБ), `noreply` (сервер не ответил на TLS),
  `connfail`, `udp-noreply`, `proxy-down`, `any`. Пока VPN работает, приложение читает журнал
  соединений движка; первое подходящее правило срабатывает. `use`, `proxy`, `try` и `autofix`
  переносят домен в слот движка без перезапуска (`try` и `autofix` сначала проверяют варианты в
  фоне); `notify` — уведомление, `ignore` — не реагировать. Защита от зацикливания: пауза
  10 минут на правило и домен, не больше 30 действий в час. Правила `@on` ставьте перед
  основной стратегией.

## 0.21.0

- **Скрипты, этап 2: подбор прямо в стратегии, без перезапуска движка.**
  ```
  @sites dc = discord.com gateway.discord.gg cdn.discordapp.com
  @for dc
  @try
    --disorder 1
  @or
    --oob 3
  @or
    -C {proxy:termux}
  @end
  ```
  Каждый вариант `@try` становится группой движка со своим «слотом» (новый ключ движка
  `--slot`). VPN сразу кладёт сайты в слот найденного ранее варианта (или первого), а приложение
  в фоне проверяет варианты тестовым движком вне VPN и переносит сайты в слот победителя прямо
  в работающем движке — без перезапуска: новые соединения идут новым вариантом, открытые не
  рвутся. Победитель запоминается отдельно для Wi-Fi и мобильной сети на сутки (изменение
  вариантов сбрасывает его). `@fallback … @or … @end` — варианты как группы `--auto` движка: он
  сам переходит к следующему, когда видит блокировку. Блоки `@try` ставьте перед основной
  стратегией. Под полем стратегии видно варианты и выбранный в этой сети.
- **Скрипты в командной строке, этап 1** (план: `docs/scripting.md`). Строки, начинающиеся с `@`,
  выполняет приложение, остальное — обычная командная строка движка:
  - `@set имя = значение` и дальше `$имя` или `${имя}` — переменные;
  - `@include имя` — вставить стратегию из «Моих стратегий» по её имени;
  - `@if wifi` / `@if mobile` / `@if not …`, `@else`, `@end` — разное для Wi-Fi и мобильной сети;
    при смене типа сети VPN сам перезапускает движок с нужным вариантом (туннель не рвётся,
    открытые соединения переподключаются);
  - `@block Имя … @end` — именованный блок, под полем стратегии у него появляется переключатель.
- Под полем стратегии со скриптом: ошибки с номером строки и итоговая команда движка для Wi-Fi и
  для мобильной сети. Самопроверка, редактор настроек и проверка «текущей стратегии» работают с
  собранной стратегией. Стратегии без `@` не меняются никак.

## 0.19.1

- **Исправлено: многострочная стратегия теряла всё после первого комментария.** «Мои стратегии»
  хранили стратегию одной строкой и заменяли переводы строк пробелами; после применения из списка
  командная строка из настроек (`# === … ===` перед каждым блоком) превращалась в одну строку, и
  первый комментарий скрывал всё остальное — маршруты приложений, Telegram через прокси и основную
  стратегию. Теперь переводы строк сохраняются, а заголовок `# === … ===` заканчивается на
  закрывающих `===`, так что уже склеенные стратегии снова работают без правки.
- Самопроверка, «strategy command line»: предупреждает, если `#` скрывает опции на своей строке.
- «Telegram calls (UDP)» учитывает Telegram, направленный в прокси в самой командной строке
  (`{ipset:telegram}`), и есть ли у этой группы `--udp-proxy`.

## 0.19.0

- **Автоподбор для неоткрывшихся сайтов.** «Монитор» → «Автоподбор» или «Настройки» →
  «Стратегия» → «Автоподбор для неоткрывшихся сайтов». Приложение берёт из журнала текущей
  VPN-сессии сайты, которые заблокировались, зависли на 16–20 КБ или не ответили на TLS (можно
  добавить сайт и вручную), и проверяет их вне VPN: сначала без обхода, потом встроенные
  стратегии, несколько дополнительных и ваши прокси (основной и «Другие прокси»). На каждый
  вариант — один запуск тестового движка, все сайты сразу. Для каждого сайта видно, что его
  открыло; «Применить» даёт сайту своё решение: свою стратегию или свой прокси, раньше основной
  стратегии (после исключений и маршрутов приложений). Список «Сайты со своим решением» — с
  кнопкой «Убрать». В «Командной строке из настроек» каждое решение — отдельный блок
  `# === Автоподбор: … ===`. VPN применяет решения при следующем запуске.

## 0.18.2

- Самопроверка, «Telegram calls (UDP)»: вместо пустого имени пишется «the main proxy адрес», и
  если среди ваших прокси есть прокси с UDP, он назван прямо в подсказке.
- «built-in lists update»: список, который на телефоне ещё не создан (например, `exclude` при

## 0.18.1

- **«Сохранить в файл» для отчётов.** Рядом с «Поделиться отчётом» в самопроверке и в подборе
  стратегий — кнопка, которая сохраняет отчёт целиком туда, куда выберете (например, «Загрузки»):
  оттуда его можно прикрепить в чат в браузере или в другом приложении, куда «Поделиться» не
  отправляет. Журнал так уже умел (кнопка «Сохранить» на экране журнала).
- **Редактор настроек (JSON).** «Настройки» → «Общие» → «Редактор настроек»: все настройки и
  сохранённые стратегии одним текстом (тот же формат, что у экспорта, но без списков доменов).
  «Проверить» показывает ошибки с номером строки: синтаксис JSON, неверный тип (`"ipv6": "yes"`),
  недопустимое значение (`"dns_mode"` только PLAIN, DOH, DOT, DNSCRYPT), неизвестную стратегию,
  неизвестные ссылки `{app:…}`/`{proxy:…}`/`{list:…}` в командной строке, неверный адрес прокси.
  Неизвестные ключи — предупреждение. «Применить» доступно только после проверки без ошибок;
  удалённая настройка возвращается к значению по умолчанию.
- В редакторе списка доменов прямо под текстом видно, какие строки не домены и будут отброшены.

## 0.17.0

- **DoH по HTTP/2.** Серверы, которые не принимают HTTP/1.1 (Quad9 DoH, bortzmeyer, BlahDNS
  отвечают 505, a-and-a и CIRA — 400), теперь работают: на первый такой ответ ByeZapret
  переподключается с ALPN `h2` и дальше говорит с этим сервером по HTTP/2. Свой минимальный
  клиент без библиотек: запросы идут друг за другом по одному соединению. Если сервер не
  соглашается на HTTP/2, в самопроверке и журнале так и написано.

## 0.16.1

- **Самопроверка: звонки Telegram.** Новая строка «Telegram calls (UDP)». Звонкам нужен UDP:
  если Telegram идёт через прокси без UDP (Tor), проверка предупреждает, что сообщения пройдут,
  а звонки нет, и советует прокси с UDP (zapret-termux). Если у прокси UDP включён, через него
  отправляется STUN-запрос (stun.cloudflare.com, stun.l.google.com) и видно, передаёт ли прокси
  UDP на самом деле. Без прокси для Telegram — подсказка смотреть строки STUN.

## 0.16.0

- **Встроенные списки обновляются без обновления приложения.** Списки `proxy`, `telegram`,
  `exclude` и диапазоны адресов Telegram скачиваются из репозитория проекта вместе с
  автоматической проверкой обновлений (раз в 12 часов) или кнопкой «Обновить сейчас» в разделе
  «Списки доменов» → «Встроенные списки». Список, который вы меняли сами, не перезаписывается
  (видно по отметке «изменён вами, оставлен»). Скачанная версия заменяет встроенную и для новых
  списков.
- В самопроверке новая строка «built-in lists update»: репозиторий доступен и списки в нём
  корректны (ничего не сохраняет).

## 0.15.2

- **Короче журнал, когда прокси не запущен.** Если Tor (или другой прокси) выключен, движок
  писал по три строки на каждое соединение (`socks send`, `connect … FAILED`, `block detected`).
  Теперь одна строка «group N: proxy … refuses connections: is it running?», а повторы за

  сайта (сбор доменов и монитор соединений их не путают с DPI).

## 0.15.1

- **Список исключений.** В разделе «Списки доменов» переключатель «Исключения: эти сайты всегда
  напрямую»: домены из списка `exclude` идут без обхода и без прокси, раньше любых других правил
  (приложений, прокси, Telegram, стратегии). В списке уже есть госуслуги, налоговая, mos.ru и

  В «Командной строке из настроек» это первый блок.

## 0.15.0

- **Комментарии в командной строке.** Стратегию можно писать в несколько строк, а всё после `#` до
  конца строки — комментарий, как в скриптах. Длинные стратегии делятся на подписанные блоки.
- **Ссылки в командной строке:** `{app:пакет,…}` — приложения для `--apps`, `{proxy}` и
  `{proxy:имя}` — основной или названный прокси для `-C`, `{ipset:telegram}` — адреса Telegram
  для `--ipset` (вдобавок к `{fake:…}` и `{list:…}`). Если в стратегии есть `--apps`, VPN сам
  включает определение приложений; если есть `-C`, прокси-приложения идут мимо VPN.
- **«Командная строка из настроек»** в разделе «Стратегия»: всё, что выбрано переключателями
  (приложения напрямую и через прокси, свои стратегии приложений, сайты через прокси, Telegram,
  основная стратегия), показано одной командной строкой с блоками-комментариями. Её можно
  скопировать или перенести в свою стратегию: тогда переключатели маршрутов выключаются, чтобы
  ничего не дублировалось, а строка сохраняется в «Моих стратегиях».
- Самопроверка проверяет, что все ссылки в стратегии находятся (приложение установлено, прокси с
  таким названием есть).
- Убрано разрешение от удалённого модуля Tor.

## 0.14.0

- **Несколько прокси.** В разделе «Сайты через прокси» появился список «Другие прокси»: кроме

- Самопроверка проверяет каждый добавленный прокси и Telegram через выбранный для него прокси.

  сервера Telegram через Tor (1,4 с).

## 0.11.4

- **Быстрый первый ответ DNS в режиме DNSCrypt.** При запуске VPN все выбранные серверы
  измеряются одним запросом, как это делает dnscrypt-proxy. Первым сразу спрашивается
  самый быстрый из отвечающих. Раньше первые запросы шли по порядку списка, и на телефоне
  первый ответ занимал 4,7 с. В журнал пишется, сколько серверов отвечает и какие быстрее всех.
- **Telegram через прокси.** Переключатель в *Настройки → Сайты через прокси*. Приложение
  Telegram подключается к своим IP без имён, поэтому через прокси оно идёт по диапазонам адресов
  Telegram, а его сайты по списку `telegram`. Работает через Tor. Звонкам нужен прокси с UDP.
  Самопроверка подключается к серверу Telegram через прокси.
- **Исправлены списки IP (`--ipset`) в движке.** На телефонах адреса IPv4 приходят в виде
  IPv6 (`::ffff:…`) и не совпадали ни с одной записью списка. Это та же причина, что у
  ошибки DNS в 0.11.1.
- Проверено на телефоне: после 0.11.3 строка «encrypted DNS through the engine» снова OK.

## 0.11.1

- **Исправлен зашифрованный DNS в VPN** (DoH, DoT, DNSCrypt). На телефонах движок хранит
  UDP-адреса в виде IPv6 (`::ffff:10.10.10.53`), а адрес перенаправления DNS сравнивался как

  первый.
- Рекомендация DNS в самопроверке учитывает режим DNSCrypt и правильно называет раздел
  настроек.

## 0.11.0

- **Модуль Tor.** Tor без второго приложения. Отдельный APK «ByeZapret Tor» (около 15 МБ на
  архитектуру), внутри Tor 0.4.9.14 от Guardian Project и транспорты мостов obfs4, meek,
  WebTunnel и Snowflake (IPtProxy).
- Модуль скачивается кнопкой в *Настройки → Сайты через прокси → Модуль Tor* и сверяется
  с `SHA256SUMS.txt`. Используется, только если подписан тем же ключом, что и приложение.
  Управлять им может только ByeZapret.
- Tor модуля запускается и останавливается вместе с VPN. Он слушает SOCKS5 по адресу прокси
  (по умолчанию `127.0.0.1:9050`), сам модуль работает вне VPN.
- Мосты: без мостов, встроенные из Tor Browser (Snowflake, obfs4, WebTunnel, meek) или свои
  строки. Проценты подключения и ошибки Tor видны в настройках и в журнале.
- Переключатель «Использовать модуль Tor»: модуль или Orbot/InviZible.

  - проверка скорости серверов;
  - можно выбрать несколько серверов: первым спрашивается самый быстрый из отвечающих;
  - свой сервер добавляется по ссылке `sdns://`.
- Самопроверка проверяет каждый выбранный сервер.
