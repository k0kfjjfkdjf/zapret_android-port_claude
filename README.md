# ByeZapret

> **Почему новое название.** До версии 0.9.7 приложение называлось ZapretDroid. На GitHub
> есть отдельный проект с точно таким же именем —
> [ezxidze/ZapretDroid](https://github.com/ezxidze/ZapretDroid), — устроенный совсем
> по-другому и никак с этим не связанный. Чтобы их не путали, это приложение теперь
> называется **ByeZapret**. Идентификатор пакета (`io.github.zapretdroid`) оставлен прежним:
> обновления ставятся поверх, настройки сохраняются, старые резервные копии импортируются.

Обход DPI на Android **без root**: обычное приложение, которое работает через системный VPN
(`VpnService`). Трафик никуда не уходит — «VPN» локальный, он нужен только чтобы перехватить
соединения и применить к ним техники обхода в духе [zapret](https://github.com/bol-van/zapret).

> Отдельный проект в этом же репозитории: **[zapret-termux](https://github.com/k0kfjjfkdjf/zapret_android-port_claude/tree/termux-zapret-udp-script)**, tpws из zapret с поддержкой UDP в Termux + proot-distro (ветка `termux-zapret-udp-script`).

## Как это устроено

```
Приложения ─► VpnService (TUN) ─► hev-socks5-tunnel ─► ByeDPI (SOCKS5 на 127.0.0.1)
                                                        └─► сеть через обычные сокеты
```

- **[ByeDPI](https://github.com/hufrea/byedpi)** — движок десинхронизации: split, disorder, OOB,
  разбиение TLS-записей, фейковые пакеты с низким TTL (через `vmsplice`/`splice`, root не нужен),
  фейковые UDP-датаграммы для QUIC, автоматическое переключение стратегий при сбоях.
- **[hev-socks5-tunnel](https://github.com/heiher/hev-socks5-tunnel)** — переводит пакеты из TUN
  в SOCKS5-соединения (TCP и UDP).
- Само приложение исключено из VPN, поэтому сокеты движка идут в сеть напрямую.
- VPN-сервис работает в отдельном процессе `:engine`, который завершается после каждой сессии:
  у обеих нативных библиотек глобальное состояние.

### Почему не nfqws

nfqws/nfqws2 из zapret работают с сырыми пакетами через NFQUEUE — это требует root. Без root
доступны только техники уровня сокетов (то, что умеет tpws и ByeDPI). Поэтому часть стратегий
zapret на Android без root не воспроизвести.

## Возможности

- Включение одной кнопкой, плитка в шторке, уведомление с кнопкой остановки.
- Готовые стратегии и своя командная строка движка.
- **Интерфейс ByeByeDPI** (*Настройки → Интерфейс ByeByeDPI*): все экраны ByeByeDPI 1.8.2 —
  главный экран, настройки (редактор и командная строка), выбор приложений, подбор стратегий,
  режим прокси. Работает на VPN-сервисе и движке ByeZapret, поэтому в его командной строке
  работают и параметры ByeZapret (`{fake:...}`, `{list:...}`, маркеры tpws, `--mss`,
  `--udp-proto-fake`…). Стратегия, DNS, IPv6 и список приложений общие для обоих интерфейсов;
  вернуться — пункт «Интерфейс ByeZapret» в меню.
- **Списки доменов (`-H`) и для UDP:** движок определяет хост UDP-потока по SNI в QUIC Initial
  (включая Chrome с Kyber, где ClientHello в двух пакетах), по ответам DNS, прошедшим через
  него, и по Discord IP discovery. Группы стратегий по сервисам (YouTube, Discord…) теперь
  действуют и на QUIC и голос, а не только на TCP. TCP без SNI тоже узнаётся по DNS.
  Ограничения: имена из DNS видны только при обычном DNS — с частным DNS Android (DNS over
  TLS) или DNS-over-HTTPS в браузере их нет; учитываются только ответы DNS-серверов VPN на
  запросы, прошедшие через движок; у адреса CDN бывает несколько имён (хранятся до четырёх).
  ClientHello с ECH сверяется по внешнему SNI (`public_name`), не по DNS. Первый Initial
  Chrome с Kyber уходит ещё с запасной группой (SNI во втором пакете).
- **Зашифрованный DNS** (*Настройки → Сеть*: «DNS over HTTPS» или «DNS over TLS»; Cloudflare,
  Google, Quad9, AdGuard, AdGuard Family, Cloudflare Security, Cloudflare Family или свой
  `https://…`/`tls://…`). VPN выдаёт приложениям адрес
  `10.10.10.53`; движок отправляет эти запросы в резолвер приложения, тот спрашивает сервер по
  зашифрованному соединению — по IP и без SNI (сертификат сервера проверяется) — и кэширует
  ответы на их TTL. Провайдер не видит и не подменяет ответы (NXDOMAIN для YouTube от 8.8.8.8),
  а имена для `-H` известны всегда: ответы проходят через движок. Если сервер не отвечает,
  пробуются остальные из списка с той же фильтрацией. TCP на `10.10.10.53` отклоняется сразу, поэтому «Частный DNS»
  Android в режиме «Автоматически» без задержки переходит на обычный запрос, который идёт в
  резолвер. Тестер, глубокая проверка и «Проверка функций» резолвят так же; проверка функций
  показывает, проходят ли DoH и DoT у каждого сервера в этой сети.
- **Обновление из приложения:** раз в 12 часов (или кнопкой в настройках) приложение смотрит
  релизы на GitHub; если есть версия новее, показывает, что изменилось, скачивает APK под
  архитектуру телефона, сверяет SHA-256 с `SHA256SUMS.txt` релиза и открывает системный
  установщик. «Позже» больше не предлагает эту версию сама. Обновляются сборки начиная с 0.9.3
  (один ключ подписи).
- **Сайты через прокси** (*Настройки → Сайты через прокси (Tor или свой)*) — для сервисов, которые отказывают
  российским адресам сами, а не по требованию РКН (ChatGPT, Gemini, Claude, Copilot, Grok,
  Perplexity): обход DPI тут бессилен, сайт должен видеть адрес за границей. Домены из списка
  (`proxy`, редактируется в «Списках доменов») идут через SOCKS5-прокси — Tor из Orbot или
  InviZible Pro в режиме прокси (их собственный VPN выключен; Android разрешает один VPN).
  Движок передаёт прокси имя домена из SNI, и Tor резолвит его на выходном узле; UDP (QUIC)
  таких доменов отбрасывается (если не включено «UDP тоже через прокси»), приложения
  переходят на TCP. Адрес прокси — только `IP:порт`. Orbot запускается сам (его
  публичный intent), приложение Tor остаётся вне нашего VPN. Медленно, и часть сайтов
  показывает для Tor капчу.
- **Приложения через прокси или напрямую** (*Настройки → «Приложения: через прокси или
  напрямую»*) — для каждого приложения: «обычно», «через прокси» (весь его трафик идёт в Tor или
  свой прокси, что бы ни было в списках) или «напрямую» (без обхода и без прокси, например банки) или «своя стратегия» (свои аргументы обхода
  для этого приложения).
  hev-socks5-tunnel передаёт движку исходный адрес каждого соединения, движок спрашивает Android,
  какому приложению оно принадлежит (`getConnectionOwnerUid`, на Android 7–9 — `/proc/net`), и
  выбирает группу `--apps`.
- **Telegram через прокси** (*Настройки → Сайты через прокси → «Telegram через прокси»*) —
  приложение Telegram подключается к своим IP без имён, поэтому список доменов его не ловит:
  отдельная группа движка по диапазонам адресов Telegram (`--ipset`, из
  core.telegram.org/resources/cidr.txt) плюс список сайтов `telegram` (telegram.org, t.me и
  другие). Работает через Tor; звонкам (UDP) нужен свой прокси с UDP и «UDP тоже через
  прокси». Самопроверка подключается к серверу Telegram через прокси.
- **DNSCrypt и публичный список серверов** (*Настройки → Сеть → DNSCrypt → Серверы DNSCrypt и
  DoH*) — свой клиент
  DNSCrypt v2 (X25519, XSalsa20/XChaCha20-Poly1305, проверка сертификата сервера по ключу
  провайдера Ed25519; при усечённом ответе — TCP). Список серверов dnscrypt-resolvers
  (`public-resolvers.md`, как в dnscrypt-proxy и InviZible Pro) скачивается с проверкой
  подписи minisign и обновляется раз в 3 дня. Поиск по имени и описанию, фильтры как
  `require_*` в dnscrypt-proxy: DNSCrypt/DoH, DNSSEC, без журналов, без фильтрации, IPv6;
  проверка скорости ответа. Можно выбрать несколько серверов — первым спрашивается самый
  быстрый из отвечающих — и добавить свой по ссылке `sdns://`. DoH-серверы из списка тоже
  работают. Блокировка по спискам работает и в этом режиме.
- **Блокировка рекламы, вредоносных и «взрослых» сайтов** (*Настройки → Сеть → «Блокировка в
  ByeZapret»*, в режимах DoH, DoT и DNSCrypt) — резолвер приложения отвечает 0.0.0.0 на имена из списков HaGeZi (Multi NORMAL,
  Threat Intelligence mini, NSFW); домен блокируется вместе с поддоменами. Списки
  скачиваются по запросу и обновляются раз в 3 дня, хранятся компактно (8 байт на домен).
  Свои списки `dns-block` и `dns-allow` действуют всегда, `dns-allow` главнее. Плюс готовые
  фильтрующие серверы: AdGuard, AdGuard Family, Quad9, Cloudflare Security и Family; при сбое
  сервер заменяется только таким же по фильтрации.
- **InviZible Pro с GitHub** (*Настройки → Сайты через прокси → InviZible Pro*) — кнопка скачивает
  последний InviZible Pro из его релизов на GitHub (файл под архитектуру телефона, с проверкой
  SHA-256, которую сообщает GitHub) и ставит установщиком Android. Свой модуль Tor (0.11–0.13)
  убран: InviZible делает то же и больше (мосты, их поиск, DNSCrypt).
- **Свой локальный прокси, в том числе с UDP** — вместо Tor можно указать свой SOCKS5
  (`IP:порт`, например sing-box, Xray или NekoBox в режиме SOCKS). Переключатель «UDP тоже
  через прокси» отправляет через него и UDP сайтов из списка (QUIC, звонки) по SOCKS5 UDP
  ASSOCIATE — у каждого UDP-сокета своя ассоциация с прокси. Самопроверка шлёт DNS-запрос
  через UDP-реле прокси и сообщает, умеет ли он UDP. Для Tor оставьте выключенным.
- **UDP через туннель:** один UDP-сокет приложения может слать нескольким серверам (WebRTC:
  STUN, TURN, медиасервер) — каждый пакет уходит своему адресату, ответы приходят от всех, у
  каждого адресата своя группа и свой счёт `--udp-desync`. В исходном ByeDPI (и ByeByeDPI)
  все пакеты сокета уходили первому адресату. Сессии UDP в туннеле живут 5 минут без трафика.
- **Из zapret:**
  - фейковые нагрузки из zapret2 (QUIC Initial, TLS ClientHello, Discord, STUN…) —
    `--fake-data {fake:имя}`, кнопка «Вставить фейковую нагрузку», пресеты «TCP + QUIC/UDP»
    и «Discord и звонки»;
  - подбор стратегии в духе `blockcheck`: перебор стратегий на выбранных сайтах (в том числе
    59 стратегий сообщества ByeByeDPI и списки сайтов: видеосерверы YouTube, Telegram,
    Discord, соцсети, Cloudflare), по каждому сайту — этап, на котором случился сбой, тайминги,
    статус HTTP, обрезка или зависание ответа, редирект на страницу блокировки; результат
    применяется одним нажатием; режим «UDP»: проверка QUIC (HTTP/3) каждого сайта настоящим
    QUIC Initial и STUN-серверов звонков через UDP ASSOCIATE движка; отчёт каждого прогона
    отдельным файлом с кнопкой «Поделиться»; коды причин сбоя (`+ r t f c m`), ответ больше
    64 КБ считается открытым (обрыв ТСПУ на 16–20 КБ отмечается отдельно), цели с путём и
    `big:` (не меньше 200 КБ, с переходом по редиректам), группа «Discord полностью», проверка
    TLS 1.2 и 1.3 по отдельности;
  - **глубокая проверка**: все стратегии против сотен и тысяч доменов из групп сайтов и
    хост-листов, свои таймаут, число попыток, параллельность и паузы, работа в фоне с
    уведомлением; результат — матрица `matrix.csv` (домен × стратегия), сводка и zip-архив;
  - **мультистратегия** из результатов глубокой проверки (как `blockcheck multi` в
    zapret-termux): главная стратегия плюс до пяти дополнительных, каждая для своих доменов
    через группы `--hosts {list:multi_N}`;
  - маркеры позиций tpws: `method`, `host`, `endhost`, `sld`, `midsld`, `endsld`, `sniext`
    (`--split midsld`, `--tlsrec sniext+1`…);
  - модификации HTTP из tpws в `-M`: `hostcase`, `hostspell=`, `hostdot`, `hosttab`,
    `hostnospace`, `hostpad=N`, `methodspace`, `methodeol`, `unixeol`;
  - каталог списков из активно обновляемых репозиториев: Flowseal/zapret-discord-youtube
    (самая популярная сборка zapret для Windows), itdoginfo/allow-domains, Re-filter,
    zapret.cfgs; скачивание и обновление одной кнопкой;
  - списки хостов в формате zapret (импорт, gzip, загрузка по ссылке) и область применения:
    все сайты / только список / все, кроме списка; `{list:имя}` в аргументах;
  - autohostlist как отладочная функция: запись доменов, где блокировка видна даже со
    стратегией, и добавление их в список.
- **Проверка функций** (Настройки): около 80 проверок устройства, движка и сети за две-три минуты
  (разрешения, частный DNS, оптимизация батареи, движок против локальных серверов — TCP с
  разрезом и UDP с фейками, все пресеты, DNS, HTTPS, QUIC и STUN без обхода и с текущей
  стратегией) и отчёт с концом журнала для отправки разработчику.
- Журнал движка (`--conn-log`): время первого UDP-ответа, повторы Discord IP discovery
  (причина долгого «Подключение…»), неудачные и медленные TCP-соединения.
- Карточка стратегии на главном экране: выбор из пресетов, закреплённых и истории
  (стратегии из подбора, глубокой проверки и редактора запоминаются сами), смена на лету с
  переподключением; пауза в уведомлении; предупреждение о частном DNS; экспорт и импорт
  настроек, стратегий и списков одним JSON-файлом.
- Сбор доменов приложения: VPN пропускает только выбранное приложение, все его хосты
  (с отметкой, где была блокировка) сохраняются списком.
- Фейковые QUIC Initial со случайным разрешённым SNI на каждый фейк (`{fake:quic_sni}`).
- Журнал всего приложения в одном файле: действия в интерфейсе, изменения настроек, сессии
  VPN, смены сети, подбор стратегии, вывод движка и туннеля, точная команда запуска, ошибки
  со стеком и падения. Источник каждой строки (`ui`, `vpn`, `test`, `byedpi`, `hev`), фильтры,
  отправка/сохранение; при запуске приложения или сессии VPN журнал больше 4 МБ обрезается до
  последних ~2 МБ (на месте, вывод движка продолжает писаться в тот же файл); вывод движка за
  одну сессию ограничен 8 МБ, дальше только в logcat. В облачный бэкап журнал не попадает.
- **Автоматизация:** активность `ToggleActivity` включает, выключает и меняет стратегию из
  других приложений и скриптов — см. [docs/automation.md](docs/automation.md). Она не защищена
  разрешением: любое приложение на телефоне может её вызвать.
- DNS-сервер, IPv6, раздельное туннелирование по приложениям.
- Поддержка «Постоянного VPN» Android (автозапуск при загрузке:
  *Настройки → Сеть → VPN → ByeZapret → Постоянная VPN*).
- Интерфейс на русском и английском, Material You. Android 7.0+ (API 24).

Движок — форк ByeDPI в `app/src/main/cpp/engine` (изменения перечислены в
[UPSTREAM.md](app/src/main/cpp/engine/UPSTREAM.md)).

## Сборка

```sh
git clone --recursive https://github.com/k0kfjjfkdjf/zapret_android-port_claude.git
cd zapret_android-port_claude
./gradlew assembleDebug
```

Нужны JDK 21 (или 17), Android SDK (platform 36), NDK 27.2.12479018 и CMake 3.22.1.
APK для всех ABI и универсальный APK появятся в `app/build/outputs/apk/debug/`.
Модуль Tor собирается отдельно: `./gradlew :tor:assembleDebug`, его APK — в
`tor/build/outputs/apk/debug/`.
CI (GitHub Actions) собирает их на каждый push — смотрите артефакты сборки.

Подписанный релиз: задайте переменные `ZAPRETDROID_KEYSTORE`, `ZAPRETDROID_KEYSTORE_PASSWORD`,
`ZAPRETDROID_KEY_ALIAS`, `ZAPRETDROID_KEY_PASSWORD` и запустите `./gradlew assembleRelease`.

## English

ByeZapret is a rootless DPI bypass for Android. It runs a local VPN (`VpnService`) that feeds
traffic through [hev-socks5-tunnel](https://github.com/heiher/hev-socks5-tunnel) into the
[ByeDPI](https://github.com/hufrea/byedpi) desync engine; nothing goes to a remote server of
the project. Included: zapret-style host lists and tpws position markers, zapret2 fake payloads,
a blockcheck-like strategy finder with a deep check and multi-strategies, encrypted DNS (DoH,
DoT, DNSCrypt), DNS blocking of ads and malware sites, routing selected domains through Tor
(a downloadable module) or your own SOCKS5 proxy, and automation through an activity intent.
Packet-level nfqws techniques need root and are out of scope. The documentation is in Russian,
in [docs/](docs/). Build with `./gradlew assembleDebug` after a recursive clone (JDK 17 or 21,
SDK 36, NDK 27.2.12479018, CMake 3.22.1).
